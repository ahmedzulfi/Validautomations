Docs

Connect real agents to a native Rust UI

Each recipe is a complete app: what you get, the Cargo.toml, about 50 lines of code and how to run it. They all use glowkit-stream: an adapter turns the agent's stream into events, a Session folds them into a thread, and AgentThread draws it with glowkit's AI components.

Recipes

Local LLM chat with Ollama

Build a native Rust GUI for Ollama, vLLM or LM Studio: streaming chat, reasoning and tool calls in about 50 lines with glowkit-stream, egui and async-openai.

A rig agent UI

Give a rig agent a native window: streamed answers, tool calls with live arguments and results, and reasoning, drawn by glowkit's AgentThread in Rust.

A desktop front-end for an AG-UI agent

A native Rust AG-UI client for LangGraph, CrewAI, Mastra, Pydantic AI or ADK agents: streamed text, tool calls and human-in-the-loop approvals, built with egui.

A native client for a Vercel AI SDK backend

Point a native Rust desktop app at the Vercel AI SDK route you already have: UI message streams, tool calls and reasoning drawn by glowkit. No webview.

An ACP coding-agent viewer

Watch an Agent Client Protocol coding agent in a native Rust window: plans, tool calls, file diffs and permission requests over stdio, drawn with glowkit.

The three parts

Adapters

AG-UI, the Vercel AI SDK UI message stream, the Agent Client Protocol, rig and async-openai (Ollama, vLLM, LM Studio, OpenRouter) all map onto one event model.

Session

Folds events into a thread: messages, reasoning, tool calls with partially streamed JSON arguments, approvals, plans, sources and errors. Plain data you can inspect and save.

AgentThread

Renders the session with streaming Markdown, tool-call cards and approval prompts, and returns the user's decisions so you can send them back to the agent.

rx.drain_into(&mut session);                        // events from any thread or runtime
let out = AgentThread::new(&mut session).show(ui);  // the whole thread
for decision in out.decisions { /* send the approval back */ }
